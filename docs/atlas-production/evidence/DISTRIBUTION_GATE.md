# Distribution evidence gate and release hold

Release remains **HOLD** and Issue #16 remains open. Passing an engineering gate does not establish legal rights. No trusted reviewer, signed disposition, complete notice package, source-delivery record, protected environment, or permission to publish is established by this work.

`atlasDistributionInventory` resolves SDK, Play and Enterprise runtime graphs into `apps/atlas-android/build/reports/distribution/`. Each inventory includes resolved artifact hashes and selected graph edges. Coordinates' license metadata is marked `UNREVIEWED`; it is not a legal determination. Graphs and hashes must be regenerated for the exact candidate. The checked-in snapshots are historical evidence, not authorization.

`atlasDistributionGate` checks Play and Enterprise artifacts; `atlasSdkDistributionGate` checks an SDK candidate using the same mechanism. Both always include a blocking finding because a verifier controlled by the candidate checkout cannot authorize distribution. They also fail closed if source status, inventories, pin, artifacts or evidence cannot be verified. The gate produces `gate.json` with blockers, including on inventory and pin errors. It compares the clean Git commit and tree, audited Meshtastic pin and inputs, SHA-256 of all three resolved graphs, exact artifact and flavor, and component coverage against a signed approval. Component entries include generated Meshtastic and TAK code, Atlas SDK and application source, and each resolved runtime coordinate. These checks are development evidence, not an independent release authority.

The detached Ed25519 signature covers the exact UTF-8 bytes of a JSON approval using schema `atlas-distribution-approval/v1`. The approval must contain `reviewer`, `recordId`, `approvedAt`, `expiresAt`, `revision`, `sourceTree`, `pin`, `flavor`, `artifactSha256`, the three `inventories` hashes, and a `rights` map covering all component coordinates and explicit source/generated components. Each rights entry has a non-unknown `license`, a disposition (`LICENSED`, `PERMISSION`, or `REVIEWED`), and an `evidence` record. `noticeDisposition` must be `COMPLETE`; `notices` names archive entries and their SHA-256 digests. `sourceDelivery` contains the source archive SHA-256, an HTTPS URL and evidence reference. A reviewer must confirm the completeness and legal sufficiency of the notice and source-delivery assertions. The tool verifies the named notices are in the artifact and the supplied source archive has the signed digest; it does **not** confirm that the URL serves the archive or decide whether the archive is legally sufficient corresponding source.

The gate accepts the key and reviewer identity from its execution environment; those values alone do **not** establish authorization. The current local workflow has no release job or protected publisher. An independent verifier and publisher, its protected implementation, trust anchor, approval controls and credentials must be established outside candidate control before publication. A repository administrator must audit historical workflows and tags, remove their access to signing credentials and publishing authority, restrict tag creation and workflow authority, and rotate any credentials whose prior exposure cannot be ruled out. Protect the publisher's environment and prevent bypass where available; independently verify the actual configuration. Updating this checkout cannot remove authority from an older workflow. No current evidence establishes these external controls. Promotion must bind approved candidate bytes to the signed output and attest the verified final artifact digest when signing changes bytes.

Public Maven publication and `publishToMavenLocal` remain blocked. No protected SDK publisher is implemented, so `atlasSdkDistributionGate` alone cannot authorize remote publication. Private binary-consumer verification uses only `apps/atlas-android/build/atlas-private-verification/repository`; user-selected paths are rejected. Publication checks for traversal and symlinks and attempts to establish owner-only POSIX permissions or Windows ACLs, refusing unsupported and known remote filesystems. These checks cannot prove that a same-user service will not expose or copy files, and cannot prevent manual delivery; the repository must run on a trusted local workspace. The private repository is for development verification only.

`atlasDistributionGateTest` exercises synthetic signed evidence, path cases, copied pin modifications, and a graph mismatch using resolved configurations. No test result grants legal approval.
