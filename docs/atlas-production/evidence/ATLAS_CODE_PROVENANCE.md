## TAK schema comparison and unresolved provenance

The local Git history examined with `git log --all -- apps/atlas-android/app/src/main/proto/takmessage.proto` lists its introduction in `e385670f114c3fc04cf7dff3cc30d9f5d4ce08ef` (2026-09-27); the introduced file has no copyright, license, upstream URL, version or creation record. This history does not establish its source, its authorship, or a rights grant. Obtain the creation record and the exact source and version from the contributor, together with any permission or applicable terms; absence of a header is not a license determination.

For a bounded technical comparison, [TAK Product Center's `takmessage.proto`](https://github.com/TAK-Product-Center/atak-civ/blob/6cefd4c83371789937a6a30aa4d7e81d84b82374/commoncommo/core/impl/protobuf/takmessage.proto) at revision `6cefd4c83371789937a6a30aa4d7e81d84b82374` uses the `atakmap.commoncommo.protobuf.v1` package and imports separate event and control definitions, whereas Atlas uses `atakmap.commoncommo.v1` and combines definitions. The two top-level message field names and numbers match, but this is not proof of copying, complete schema equivalence or provenance. The upstream [README](https://github.com/TAK-Product-Center/atak-civ/blob/6cefd4c83371789937a6a30aa4d7e81d84b82374/README.md) describes its public-domain and license position with jurisdictional qualifications and directs readers to its [license file](https://github.com/TAK-Product-Center/atak-civ/blob/6cefd4c83371789937a6a30aa4d7e81d84b82374/LICENSE.md). It does not establish which terms govern Atlas's file; third-party and jurisdictional facts require separate review.

**Interoperability concern, not an observed device failure:** Atlas's `Track` declares `course = 1` and `speed = 2`; the pinned comparison's [upstream `track.proto`](https://github.com/TAK-Product-Center/atak-civ/blob/6cefd4c83371789937a6a30aa4d7e81d84b82374/commoncommo/core/impl/protobuf/track.proto) declares `speed = 1` and `course = 2`. Both are doubles, so cross-schema consumers of the structured track fields could interpret the values in reverse. Atlas's current `CotProtobufGenerator.kt` does not populate `Track`, and `AtakPayloadParser.kt` does not map that structured field into its parsed result; the inspected `CotProtobufTest.kt` round trips the locally generated schema and does not test this cross-schema case. Confirm the intended TAK protocol revision and use an independent official-wire fixture and real peer testing before changing field numbers or claiming runtime impact. The comparison also found upstream fields absent locally; it was not an exhaustive interoperability assessment.
