## Scope

Create a standalone Kotlin/JVM library of schema-independent protobuf binary wire primitives. It must not import Android, platform UI libraries, generated messages, code generators, or application-specific protocol definitions. Compile and test it as an independent project. This is not a complete schema-aware protobuf implementation: it does not infer a field's declared meaning, apply presence/merge semantics, validate UTF-8, decode signed or ZigZag types, interpret packed fields, or implement RPC. A caller may build such policies separately.

## Required behavior

1. Encode and decode unsigned 64-bit base-128 varints. Preserve all 64 bits, including values whose high bit is set; Kotlin may represent the bits using `ULong` or a documented raw `Long`. Emit the shortest representation. Accept terminating representations of up to ten bytes, including nonminimal encodings, if their numeric value fits 64 bits. Reject truncation, a tenth byte with continuation set, or a tenth-byte payload greater than one. Never silently truncate, wrap, or loop indefinitely.
2. Read and write raw 32-bit and 64-bit fixed-width bit patterns in little-endian byte order. Reject truncated fixed-width values. The core does not interpret these bits as signed integers or floating-point values.
3. Read and write a record tag consisting of a field number and wire type. Accept field numbers `1..536870911`; reject zero and out-of-range numbers. The wire-level parser must not reject otherwise valid numbers solely because a schema compiler reserves a range. Accept wire types 0, 1, 2, 3, 4 and 5 subject to the group rules below; reject 6 and 7. Do not assume an ordering or uniqueness of fields. Tags and lengths are varints; validate their values before narrowing or using them as indices.
4. Read and write length-delimited opaque bytes, including zero-length values. Check that a declared length fits the configured limits and the remaining input before conversion, allocation, or arithmetic; reject truncation and overflow. A byte payload is not automatically a message. When a caller explicitly chooses nested-message parsing, restrict the child to exactly its declared region and its configured depth and resource budgets. Require the child to finish at its boundary; it cannot consume bytes belonging to its parent.
5. Support unknown-field skipping for varint, fixed64, length-delimited and fixed32 wire types without interpreting their content. Also safely skip deprecated groups, matching each end-group's field number to its start and enforcing the same depth and resource limits. Reject unexpected, mismatched or unterminated end groups. Provide a way to retain the exact encoded bytes of skipped fields and re-emit them in original order when requested; unknown retention is bounded by the same output limits. A raw retained field must be validated before re-emission. This does not promise canonical serialization of an entire message.
6. Enforce configurable limits on input bytes, output bytes, individual length-delimited payload, nesting depth, and total field count. Defaults are 1,048,576 bytes each for input, output and payload, depth 32, and 10,000 fields. Hard maximums are 16,777,216 bytes each, depth 64, and 100,000 fields. These are project safety choices, not protobuf format limits. Limits are nonnegative, validated at construction, inherited by nested readers, and cannot be reset by opening a child. `maxDepth = 0` permits a top-level message but no nested message or group. Count input bytes once at the root, and count fields cumulatively across all children and groups. Check limits before allocation or write; nested traversal and retained unknown fields must not bypass limits. Reject invalid configurations rather than silently substituting permissive values.
7. Distinguish normal end-of-message at an exact boundary from malformed/truncated input. Report a controlled error with a useful category for malformed input, overflow, unsupported wire type, or limit exhaustion; do not treat errors as success or return partially decoded messages as complete. A failed reader or writer must not be silently reused as though the operation succeeded. Bound all loops, slices and allocation sizes; treat inputs as untrusted.

## Independent test requirements

Tests should include independently constructed examples as well as an official generic example: unsigned 150 encodes to `96 01` and field 1 with that value to `08 96 01`, as shown in Google's encoding guide. Bytes in the following cases are independently selected applications of the generic format, not application fixtures.

| Case | Expected result |
| --- | --- |
| Varints 0, 127, 128 and 300 | `00`, `7f`, `80 01`, `ac 02` respectively |
| Largest unsigned 64-bit value | Nine `ff` bytes followed by `01`; round trip all 64 bits |
| Varint overflow and truncation | Nine `ff` bytes followed by `02`, ten `80` bytes, and lone `80` each reject |
| Little-endian fixed values | `0x12345678` -> `78 56 34 12`; `0x0102030405060708` -> `08 07 06 05 04 03 02 01` |
| Opaque length-delimited bytes | Field 1 with bytes `61 62 63` -> `0a 03 61 62 63`; empty payload is accepted |
| Explicit nested message | `0a 02 10 01` is field 1 containing a message with field 2 varint 1; a child cannot read beyond its two-byte payload |
| Unknown group | `0b 10 01 0c` is a field-1 group containing field 2 varint 1; mismatched or missing end tag rejects |

Add tests for nonminimal terminating varints, every valid wire type, tag zero and out-of-range tags, wire types 6 and 7, repeated and reordered fields, empty messages, truncated tag/fixed/payload, length overflow before allocation, nested boundary and field-count/depth/output limits at and just beyond each boundary, unknown exact-byte preservation including a nonminimal encoding, and error handling after failure. Include randomized round trips for unsigned values and lengths with a reproducible seed. Test malformed inputs where a field is valid but a later field is truncated so partial success cannot masquerade as a complete message.
