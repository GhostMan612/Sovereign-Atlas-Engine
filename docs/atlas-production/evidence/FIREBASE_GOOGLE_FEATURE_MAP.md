# Firebase and Google dependency feature map

WO-16-A3 source audit; release disposition remains HOLD. This is a source-level map, not an assertion that a particular AAR is licensed or that a merged APK was inspected. The resolved release-runtime inventories generated by the distribution audit are authoritative for coordinates, versions and dependency paths; compare their outputs for each flavor before distribution.

| Direct use | Feature and status | Scope |
| --- | --- | --- |
| `FirebaseAuth`, `FirebaseApp` in `android/sync/FirestoreSyncProvider.kt` | Anonymous authentication for cloud chat writes; optional when the operator selects Cloud-Only or Hybrid. Initialization and authentication occur on a cloud send. Missing configuration or authentication is reported as unavailable. | Both flavors currently declare Firebase Auth through common `implementation`; Enterprise cloud has not been authorized for removal. |
| `FirebaseFirestore` in the same provider | Writes `chat_messages` by message ID; optional cloud chat. The application contract has no cloud read/subscription path. This is not evidence of end-to-end delivery or of a cloud receive feature. | Both flavors declare Firestore through common `implementation`, with Firebase BOM 33.16.0. |
| `AppServices.kt`, `AtakBroadcaster.kt`, `SyncProvider.kt` | App wiring keeps the provider lazy; the broadcaster selects cloud only for Cloud-Only or Hybrid and retains multicast for Mesh-Only or Hybrid. | `app/build.gradle` and root `build.gradle` | Google Services Gradle plugin 4.5.0 is a build-time plugin, conditionally applied when local `google-services.json` exists. It is not itself proof of a runtime artifact or configured cloud credentials. | Both flavors. |

The shared Gradle declarations mean neither flavor has been shown Firebase-free. The Firebase BOM is a version platform, while Firestore and Auth resolve their own transitive graphs, including Google Play services where selected by Gradle. Exact resolved components, paths, AAR packaging and license metadata must be taken from the generated variant inventories and reviewed; group names alone do not establish proprietary status. No Google dependency has been classified unused solely because its APIs are not imported: transitive runtime use requires dependency-specific review.

`SyncProvider` exposes authentication and push only. There is no evidence in this source audit of cloud message retrieval. Mesh-profile chat currently sends CoT through multicast; it does not invoke the Meshtastic radio supervisor for chat. Cloud writes are not initiated for mesh-only or radio-silence sends. An existing authenticated Firebase session can remain in process after profile changes, but a subsequent mesh-only send does not invoke the provider.

The settings repository serializes profile transitions with a generation-based cloud policy coordinator. Chat obtains authorization before starting authentication and revalidates the same generation immediately before starting the Firestore write. A transition invalidates prior generations; operations queued before submission cannot initiate a new authentication or write under a stale generation. The routing tests exercise queued and concurrent sends, transitions during authentication, stale generations, and transitions immediately before and after submission. Host tests do not establish Firebase runtime behavior.

Chat write results distinguish `BLOCKED`, `CANCELLED_BEFORE_SEND`, `SUBMITTED`, `CONFIRMED`, and `FAILED`. Cancellation before send refers to the chat write, not to an authentication request that may already have started. A timeout after submission is `SUBMITTED`, meaning delivery remains unconfirmed. `FAILED` reports the operation's failure result; it is not proof that no remote effect occurred. Firebase may retain an authenticated session, refresh credentials, or transmit a previously submitted queued write after a profile transition. The coordinator cannot revoke an already-submitted request or guarantee silence from Firebase's own background activity. A retry can therefore duplicate a logical message.
