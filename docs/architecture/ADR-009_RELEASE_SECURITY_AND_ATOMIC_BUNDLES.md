# ADR-009: Release Security Hardening, Loopback Socket Isolation, and Atomic Bundle Rollback

## Status
ACCEPTED / IMPLEMENTED

## Context
Work Order 04 (`WO-04_CERTIFICATION_AND_RELEASE.md`) and `specs/OFFLINE_DATA_LICENSE_SECURITY.md` require:
1. Security review and socket-level verification of the local HTTP tile server (`PackTileServer`), specifically guaranteeing loopback-only binding (`127.0.0.1`), defense-in-depth against path traversal (`..`, encoded segments, non-canonical paths), and clean port/lifecycle recovery.
2. Checksum verification and atomic update/rollback for offline bundles so that a truncated download or tampered payload never corrupts an existing valid bundle on disk.
3. Fail-closed release signing enforcement and an evidence-backed dataset license, provenance, privacy, and SBOM catalog.

Inspection of `PackTileServer.kt` revealed that `ServerSocket(port, 4)` used the two-argument constructor, which binds to the wildcard address (`0.0.0.0`) rather than strictly `InetAddress.getLoopbackAddress()`. While URLs generated by `tileUrl()` pointed to `127.0.0.1`, the listening socket itself was reachable from local network interfaces.

## Decision
1. **Strict Loopback Binding (`PackTileServer`):**
   - Bind `ServerSocket(port, 4, InetAddress.getLoopbackAddress())` so the server listens exclusively on `127.0.0.1` (`isLoopbackAddress == true`).
   - Expose `boundAddress(): InetAddress?` for deterministic security verification in unit tests.
2. **Canonical Path Traversal Defense (`PackTileServer`):**
   - Enforce a strict character allowlist on `packId` (`[A-Za-z0-9._-]`, rejecting leading dots and `..`) in addition to numeric `isTileRef` validation on `z`, `x`, and `y`.
   - Resolve `packsDir().canonicalFile` and `target.canonicalFile` and verify `target.path.startsWith(root.path + File.separator)` before serving any file.
3. **Checksum-Verified Atomic Bundle Persistence (`KnowledgeBundleSerializer`):**
   - Add `atomicWriteVerified(targetFile: File, content: ByteArray, expectedSha256: String): Boolean` to verify the SHA-256 digest in memory before disk I/O, write to a sibling `.tmp` staging file, re-verify the staged file's SHA-256 digest on disk, and atomically replace `targetFile`.
   - If verification fails at any stage, delete the staging file and leave any pre-existing `targetFile` intact (atomic rollback).
4. **Honest Release Gate Disposition:**
   - All host-verifiable gates are proven via deterministic unit tests.
   - Items requiring human legal sign-off (`G07`), physical Moto G execution (`G10`), or private release signing credentials (`G12`) remain explicitly marked `BLOCKED` in `RELEASE_ACCEPTANCE.md` until executed by the operator.

## Consequences
- **Positive:**
  - Zero LAN/Wi-Fi exposure of the local tile server port.
  - Cryptographic and canonical-path guarantees against corrupted or malicious offline bundles.
  - Full compliance with `RULES.md` §1.6 and `00_MASTER_PLAN.md` ("No artificial completion").
- **Negative / Neutral:**
  - `PackTileServer` cannot be accessed by external devices over LAN (intended by design).
