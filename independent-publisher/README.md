# Publisher verifier source 0.1.0 — release disabled

This portable source is a development component. A sibling directory, Python environment, WSL installation, signature test, or this version number does not create an independent publisher. It has not been transferred to an independently controlled repository or deployed under separately controlled administration. The source and its configuration must not be treated as a trust root merely because they exist here.

`provenance.py` validates an Ed25519 DSSE envelope over a custom in-toto statement against externally supplied builder keys, source allowlist, manifest digest, and exact file inventory. It authenticates what the configured key asserted; it does not prove that its owner or build environment is independent or that the build actually used the claimed source. The custom predicate is not a SLSA provenance implementation. The caller must derive file digests from the exact bytes it inspects and anchor the trust policy outside candidate control. Test keys are never trusted production identities.

`handoff.py` can copy a Linux file into a digest-checked sealed memory file descriptor and offers a single in-process consume. It does not implement a signing service, persistent anti-replay, or authority separation. The eventual signer must consume the same sealed bytes that were inspected, and must itself enforce authorization. This component has no signing, publication, approval, or release operation.

`python -m atlas_publisher.gate --candidate /absolute/candidate --manifest-sha256 DIGEST --trust-policy /trusted/policy.json --provenance /evidence/envelope.json` performs a review-only check and always exits 2. It verifies the manifest digest and snapshots each inventory file using the authenticated digest, then discards the snapshots. It does not validate license evidence or inspect the semantic contents of the files. The supplied policy and its path are not authenticated or protected by this CLI; a caller-selected or substituted policy can trust an attacker's key. Consequently, a successful inspection is meaningful only when an external authority has already secured that exact policy and process. Extra unlisted files are not checked and no directory is promoted.

The policy object has exactly `repository`, `source_ref`, `approved_source_commits` (full lowercase Git SHA-1 values), and `builders`; each builder entry contains `keyid` (SHA-256 of the raw Ed25519 public key) and `ed25519_public_key_b64`. The DSSE payload type is `application/vnd.in-toto+json`, with one signature by a configured builder. Its in-toto v1 statement uses predicate type `https://sovereignatlas.example/provenance/v1`; the predicate contains `builder`, `repository`, `source_ref`, `source_sha`, `candidate_sha256`, `build_id`, `issued_at`, and `expires_at`. Its subjects must exactly match every candidate inventory path and SHA-256. Builder, source, manifest and inventory claims must all be authenticated by the builder signature. Time validity is at most seven days; this is not durable replay prevention.

Release policy is DENY. Establishment requires an independently administered source repository and protected review/release process; independently provisioned policy, protected builder credentials and authenticated build infrastructure; trusted revision authorization; durable replay prevention; artifact-specific licensing clearance and distinct independent approval; and a separately controlled signer consuming verified bytes. None is established by this local source. Never deploy this as a publisher or grant it signing credentials in its current state.

The declared dependency is `cryptography>=45,<47`. Run tests from this directory on a native Linux filesystem in an isolated environment with that dependency installed: `python -m unittest discover -s tests -v`. No test authorizes a release.
